# 10.7 History, session, other services

Section 10.7 of the agent docs. [AGENTS.md](../../AGENTS.md) is the core (rules, commands, pitfalls, open work), loaded into every session, and lists every file in this folder; read its sections 0–2 first. "Section N" and "pitfall N" below mean AGENTS.md's numbering, and section 10.x is a file here.

- **Places:**
  - The UI's `places.js` sends `places-connect` with a `MessagePort` to the hidden `placesService.html`.
  - It uses Dexie database `browsingData2`, table `places` (history and bookmarks together, flag `isBookmarked`), with an indexed `*searchIndex` (stemmed tokens) and `*tags`.
  - Non-bookmarks older than 42 days are deleted hourly.
  - Suggestions come from an in-memory cache.
- **Session restore:** `sessionRestore.json` every 30 s (private tabs excluded), and once more as a window closes or Min quits: the window's `close` handler (`main/windowManagement.js`) holds the close, sends `save-session-before-close`, and closes once the UI answers `session-saved-before-close` (or after 2 s); Quit then quits again (`windows.quitting`). Before 2026-11-09 that last save was the UI's `beforeunload`, which never ran (pitfall 50), so a quit lost everything since the last 30 s save (suite `session-restore`). The UI only saves while its window is focused (one window saves, not all), and Min is usually closed in the background: since 2026-11-12 main tells one window to save anyway (`evenInBackground`, from `windows.savesSessionAtClose`: the last window used when quitting, or the last one open), and when Windows shuts down, restarts or signs out, which sends no `close`, the window's `query-session-end` event asks for the same save (pitfall 56). Measured (`session-restore`, 5 checks): a tab opened 5 s before is saved by Quit, by closing the last window, by Quit with the window blurred (lost before), and when Windows asks before shutting down (the suite sends that question on its own; a real shutdown wasn't tested). `restore()` uses `restoreFromFile()` for the first window, otherwise `syncWithWindow()`.
- **Downloads:** `will-download` → `download-info` to the UI. There is no custom save path (Electron's default prompt applies).
- **Reader view:** `min://app/reader/index.html?url=...` (Readability). **PDF:** `min://app/pages/pdfViewer/index.html?url=...` (pdf.js). Both may read the address in their `url` parameter and the addresses it redirected to (`isAccessAllowedFromContentPage` in `download.js`, which walks back the redirects of the last seconds, each address once since 2026-11-13: it used to follow them blindly, and a redirect loop a website had made earlier, then a PDF, made it recurse until main failed, `security-checks` B7). Main tells the UI which tab a PDF is for (`openPDF`'s `tabId`, pitfall 59).
- **Translation:** Bergamot WASM in a hidden window; models download from `services.minbrowser.org`.
- **Statistics:** daily POST to `services.minbrowser.org` unless `collectUsageStats === false`. The fork hasn't decided whether to keep this.
