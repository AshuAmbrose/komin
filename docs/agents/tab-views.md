# 10.1 Tab views

Section 10.1 of the agent docs. [AGENTS.md](../../AGENTS.md) is the core (rules, commands, pitfalls, open work), loaded into every session, and lists every file in this folder; read its sections 0–2 first. "Section N" and "pitfall N" below mean AGENTS.md's numbering, and section 10.x is a file here.

- **Lifecycle** (UI → main):
  - `webviews.add(tabId)` sends `createView` with the list of page events to forward.
  - `webviews.setSelected` sends `setView`.
  - `webviews.update(tabId, url)` runs `urlParser.parse`, then sends `loadURLInView`.
  - `webviews.destroy` sends `destroyView`.
- **Page events** reach the UI as `view-event` and are dispatched to `webviews.bindEvent(name, fn)` handlers. Main drops subframe `did-start-navigation`/`will-redirect` and subframe `did-navigate-in-page` events.
- **`callViewMethod`** calls a method or sets a property on the view's `webContents`, then replies `async-call-result`. History methods (`canGoBack`, `goBack`, `goToIndex`, ...) are called on `webContents.navigationHistory`, since the `webContents` versions are deprecated. Callers use `webviews.callAsync(id, method, argsOrCallback, callback)`.
- **Popups** reuse the default web preferences. `filterPopups(url)` in `filtering.js` blocks popups that the ad-block engine matches.
- **Internal pages are Min's to open** (since 2026-11-13, pitfall 57). A navigation, redirect or `window.open` to a `min:` address is refused (`will-frame-navigate`, `will-redirect`, the window-open handler in `viewManager.js`) unless Min started it (`loadURL`: the address bar, session restore, the error page after a failed load, the PDF viewer, the userscript install page) or an internal page did (its `initiator`). Before, a website could send its own tab, or a popup it had opened, to any internal page with parameters it chose. Extensions still can (`tabs.create`), as Chrome lets them open `chrome://` pages, so each internal page checks its own parameters.
- **The address shown while a page loads** (since 2026-11-13, pitfall 59). Main adds a last argument to `did-start-navigation` and `will-redirect`: whether the page itself started the navigation (`initiator` set). The UI (`onNavigate` in `js/webviews.js`) only shows Min's own navigations' addresses at the start; a link or a script's navigation shows its address once its page arrives (`did-navigate`), as in Chrome. And when a tab stops loading, its address is checked against the page that's there (`showLoadedAddress`, on `did-stop-loading`): a typed address that ended without a page (204 No Content, a download) goes back to the page. Before, a page could put another site's address over its own content by starting a navigation that never arrived. Code that needs the tab a response is for gets the tab's id from main (`openPDF`, `set-file-view`), not the address. Measured (`security-checks` B2): a page's own navigation to a 204 address and a typed one both leave the address bar on the page that's there.
