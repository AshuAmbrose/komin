# Branch records

Part of the agent docs. [AGENTS.md](../../AGENTS.md) is the core, loaded into every session, and its "Where things stand" has a few lines per branch. This file keeps each branch's full record as it was written when the work was done: what changed, what was measured, which runs passed. The numbers that matter for a subsystem are also in its own file in this folder. Add a branch's record here when its summary in AGENTS.md is cut down; newest last.

## The review of `chore/unlocked-remeasure` (2026-11-12, on the same branch)

Another agent read every app-code change of the branch, reran the full regression set (22 suites, 364 checks; `userscripts-real` needed a rerun after the PC's internet dropped during it) and fixed what it found:

- **The session wasn't saved when Min closed in the background** (pitfall 56). The save at close (pitfall 50) runs in the UI, which only saves while its window is focused. A new check in `session-restore` showed it: a tab opened 5 s before quitting with the window blurred was lost. Main now tells one window to save anyway (`windows.savesSessionAtClose` in `main/windowManagement.js`), and Windows shutting down (no close event) asks for the save through the window's `query-session-end` event. `session-restore` 5/5; the shutdown check sends `WM_QUERYENDSESSION` on its own (`test/e2e/send-window-message.ps1`), so a real shutdown wasn't tested.
- **Extensions got every tab's address and every site's cookies without the permission** (pitfall 55). The extension library gives every extension every API and answers whatever is asked. Found while reviewing Min's tab list, which had widened it to hibernated tabs and other tasks; `electron-workarounds` shows both with Min's checks off (an extension with only `activeTab` read a page's cookie and another tab's address). `main/extensionPermissions.js` checks permissions in the library's router, and `js/preload/extensionSupport.js` takes undeclared APIs away (section 10.9). New suite `extensions-permissions` (13 checks) with two test extensions.
- **Hibernated tabs couldn't be acted on by extensions.** Their stand-ins in the library's tab store lacked what the library calls on a tab's page, so `tabs.reload`, `tabs.update` with an address or `muted`, `tabs.goBack` and `webNavigation.getFrame` failed with a TypeError. They now load, mute or refuse as Chrome does (`ExtensionStandInTab` in `main/extensionTabs.js`). `extensions-tabs` 13/13 (4 new checks).
- **One request to main as a frame starts, instead of two** (`page-start`, in `main/userscripts.js`): the ad blocker's scriptlets and the frame's userscripts come in one answer; `cosmetic-filters-start` and `userscripts-get` are gone. The ad blocker's part is only answered to a tab's top frame now (checked in main). The saving wasn't measured on its own.
- **Smaller:** the UI no longer re-sends its tab list to main after changes the list doesn't carry (a tab's scroll position changes with every scroll); the switch that turns generic hiding rules off for a measurement moved out of the app's code (`MIN_GENERIC_COSMETICS`) into `test/e2e/old-behaviour.js` (`noGenericCosmetics`); AGENTS.md's "Where things stand" cut back to a few lines, with this file for the records.
- **After its full run, three more extension fixes** (tested by `extensions-permissions`, 22 checks, 13 failing before; `electron-workarounds`, 12): main checks that a message comes from the extension it names (the library's bridge is within reach of every extension's code, so one could pose as another, one with more permissions); optional permissions are limited to what the manifest declares, kept in `extensions.json` across restarts, and can be removed; `tabs.captureVisibleTab` needs an `activeTab` grant or access to the shown site.
- It also read the rest of the code for weaknesses, without running anything, and left a list (the next section).
- **Not done:** the branch still hasn't been packaged or used day to day (section 15).

## The security review's findings, checked and fixed (2026-11-13, on the same branch)

The previous agent's read-only review reported 14 weaknesses (A1 to A5, B1 to B9) and a list of smaller ones, none run. This session wrote `test/e2e/security-checks.js`, which tries each one on the app, and ran it before fixing anything (the maintainer's rule: no fixes for problems that don't happen). 13 failed, so they were real; A5 passed (an extension's offscreen document has no way to Min's raw IPC). Then each was fixed and the suite rerun until all 17 checks passed.

- **A1** a website sent its tab to Min's error page with a `javascript:` address as its `url`; "Try again" ran it, and it changed a setting (`securityProbe` in `settings.json`). Websites can no longer go to `min:` addresses (pitfall 57); the error page only retries web addresses and has a CSP.
- **B1** a website that had opened Settings as a popup posted it made-up settings and the page took them (tested with A1's guard off). Internal pages only take messages from themselves.
- **B2** after `location = '<other site>/nocontent'` (204), the address bar showed the other site over the first site's page. Addresses of a page's own navigations now show when they arrive; a typed one that ends without a page goes back (pitfall 59, which also made the PDF viewer and file views find their tab by id).
- **B3** a second install page for the same `.user.js` address replaced what the first page installed. **B4** an extension with no permissions opened the install page with a local file and main read it. Both fixed in `main/userscriptInstall.js`.
- **A4** `GM_xmlhttpRequest` to an allowed host that redirected elsewhere returned the other site's answer. Redirects are checked against `@connect`.
- **B5** two sign-in prompts open at once both said "Sign in to localhost", and the name typed for one site went to the other. Each prompt window keeps its own text and answer.
- **B6** a site allowed the camera got it inside another site's frame with no prompt. Frames ask in the name of the site in the address bar, as in Chrome.
- **B7** a website made a redirect loop, then showed a PDF: main's check for the PDF viewer recursed until "Maximum call stack size exceeded" (in the packaged app, an error dialog that freezes Min). The check walks each address once.
- **A2** a package with `"version": ".."` deleted every other extension and could plant folders. **A3** a `MANIFEST.JSON` written after the reviewed `manifest.json` replaced it (cookies and all sites, reviewed as "no special permissions"); `manifest.json::$DATA` too. **B8** an update server installed 1.0 over 2.0. Versions are checked, the manifest is written last and read back, colons are refused in zip names, updates must be newer (pitfall 58).
- **Left** (AGENTS.md section 15, "Security review"): B9, a decision about the ad blocker's downloaded scriptlet code, and the smaller reports, none checked yet.
- **Regressions caught by the suites while fixing:** writing the manifest last broke packages with no other file (the folder didn't exist yet); the address fix stopped the PDF viewer from opening (it found its tab by address). Both fixed before the full run. The full run (24 suites) then found one more: refusing older updates compared with the registry's version, while the update check reads the installed manifest's, so `extensions-webstore`'s faked old copy never updated. Fixed; all 24 suites, 412 checks.
